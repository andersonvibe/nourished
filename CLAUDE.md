# Nourished: handover notes for Claude

Read this first in any new conversation about Nourished. It replaces the long chat history the app grew out of.

## What it is
Glen Anderson's own Noom-style weight-loss and nutrition app (formerly "Basket to Plate"). Built for his own use first, with a possible paid Android release later. Glen is vegetarian, uses kg for weight and feet/inches for height, and improved his fatty liver and cholesterol through diet; the app's guidance leans that way (no medical claims).

- Live app: https://andersonvibe.github.io/nourished/ (GitHub Pages from `main`, root). Installed on Glen's Pixel 9 Pro as a home-screen app.
- Repo: `andersonvibe/nourished`. Claude pushes directly (commit as `Claude <noreply@anthropic.com>` so commits show as verified).
- Older Claude-artifact version: https://claude.ai/artifact/RSf4RTvCQJ8UssE7LH8hD5 (same features minus barcode camera, live web recipe search and backups; uses Claude's built-in `sample`/`db`/`user` capabilities). **The GitHub version is the main line.** Only update the artifact if Glen asks.

## Files
- `index.html`: the whole app (HTML, CSS, JS in one file, ~2,400 lines). Photos are embedded as base64 JPEGs.
- `sw.js`: service worker. Network-first with `cache: 'no-cache'` for the app's own files, cache-first for Google Fonts. **Bump `VERSION` on every release.**
- `manifest.webmanifest`, `icon-192.png`, `icon-512.png`, `icon-maskable-512.png`, `apple-touch-icon.png`: install metadata and icons (cream leaf on forest green).
- `.nojekyll`, `README.md`.

## Releasing a change
1. Edit `index.html`.
2. Bump the footer label `<span class="mono">Version N</span>` (search for `Version `) and `VERSION` in `sw.js` (`nourished-vN`) to the same N. Current: **19**.
3. Syntax-check the main script (extract the last `<script>` block and run `node --check`).
4. Test headlessly with Playwright (Chromium is at `/opt/pw-browsers/chromium`): serve files via `page.route`, stub `https://api.anthropic.com/v1/messages` (responses are **streamed SSE**) and `world.openfoodfacts.org`.
5. Commit and push. Glen closes and reopens the app to pick it up and can confirm the version number at the bottom of the Home screen.

## Architecture
- **Storage:** everything in `localStorage` on the phone. Key `basket-to-plate-v1` holds `{settings, products, meals, receipts, weights, plans, exercise, recipes}` (old key name kept so data isn't lost). Backup/restore to a JSON file in My goals (merges, never wipes).
- **Claude:** direct browser calls to the Anthropic Messages API with Glen's own key (`localStorage['basket-to-plate-key']`, never in backups or the repo), header `anthropic-dangerous-direct-browser-access: true`. Model setting: `claude-sonnet-5-5` (default) or `claude-haiku-5-5`.
  - `ask(prompt, files, opts)` streams via `streamClaude()`, handles `pause_turn`, parses JSON from the final text, salvages complete items if an answer is cut short (`salvageArray`), and collects web-search result URLs into `lastSearchUrls`.
  - `callClaude()` (non-streamed) is only used for the key test.
  - Error codes map to plain messages in `ERR` (`bad_key`, `no_credit`, `rate_limited`, `overloaded`, `backgrounded`, `network`, `truncated`…).
- **Recipe search ("What can I make?"):** `findHave()` → `askWithSearch()`, using the `web_search_20250305` server tool with `allowed_domains` = `RECIPE_SITES`. Some big sites (BBC Good Food, Allrecipes, Guardian, Serious Eats, Simply Recipes, Good Housekeeping, bbc.co.uk) **block Claude's crawler**; the API rejects the whole request if they're listed, so they're excluded and any newly reported blocked site is stripped, remembered in `localStorage['nourished-blocked-sites']`, and retried. A recipe's rating/link is only shown if its URL came back from the search (`checked`); otherwise the card offers a Google search instead. Wake lock keeps the screen on; Android kills the request if the app is backgrounded.
- **Barcode scanning:** camera via `BarcodeDetector` (Chrome on Android) or typed number → pantry first (`product.barcode`) → Open Food Facts API v2 (free, no Claude). Unknown products fall back to a label photo, which is then linked to the barcode.
- **Calorie target:** Mifflin-St Jeor BMR × activity − pace × 7700/7 kcal; floor 1,500 (men) / 1,200 (women). Protein target 1.2 g × goal weight. Exercise: MET table `EX`, counting (MET − 1) × kg × hours; "eat back" setting 0 / 0.5 (default) / 1.
- **Exercise from a screenshot (v12):** the Exercise card's "Add from a screenshot" (`exShot`, `readExShot()`, `addExShot()`) sends up to 3 screenshots (Glen uses **Pacer** on Android) to Claude, which returns activities with type/date/minutes/calories; Glen reviews, edits calories and ticks before saving. Daily steps are flagged as possibly overlapping the activity level; repeats are flagged as already logged. This is the web-app stand-in for Health Connect, which a PWA can't read.
- **Food balance:** energy density (kcal per gram as eaten), bands from Rolls' Volumetrics categories: light < 1.5, medium 1.5–4, dense > 4 (`densityOf`, `ED_LIGHT`, `ED_DENSE`). Each meal's `mix` stores kcal by band plus `w` (grams of food as eaten, drinks excluded) and `wk` (kcal of that food); ingredients may carry `eaten100` (cooked kcal/100g for dry pasta, rice, lentils) and `drink`. The day card shows kcal/g vs the WCRF goal of 1.25 (`ED_GOAL`); meals logged before v10 have no `w` and are left out. Method and sources live in `densityHelpHTML()` / `DENSITY_SOURCES`, shown in the Food balance card and the Plan explainer.
- **Meal editor:** one editor (`renderMealReview()` on `mealRes`) for new and logged meals. Tapping a meal on Today calls `editMeal()` (`mealRes.editId` set; save keeps the id). Meals with no ingredient list (from plans, recipes, ideas) become one `portion: true` item that keeps its own `mix`. "Add more to this meal" (`mealAdd`: `bc` barcode, `text` described via Claude, `pantry`) appends items; a new estimate joins a meal already being built (`takeEstimate()`). Log a meal has a Barcode mode, the Barcode page has "Add other food to this meal", and Today's Meals card has Add a meal buttons. From Today the `#p-meal` panel is moved into the `#msheet` bottom sheet (`openMealSheet()` / `closeMealSheet()` move it back to Scan). The camera scanner is shared (`startCam(prefix)`, prefixes `bc` and `ma`); barcode lookup is `fetchBarcode()`.
- **Meal photos:** a meal can have up to 6 photos (`files.m` is an array, `MAX_MEAL_PHOTOS`), e.g. prep shot + finished dish; each is shrunk to a 1568px JPEG as soon as it is picked (`shrinkPhoto`, decoding via `<img>` first because `createImageBitmap` failed on full-size Pixel photos), then all are sent in one request and the prompt says to count food seen in several photos once. Photos are only used for the estimate, not stored with the meal (localStorage space).
- **My recipes (Plan → My recipes, `S.recipes`):** Glen's own recipe book. Import (`importRecipe()`) takes any mix of a link, pasted caption/text, screenshots and a saved video (8 stills taken in the browser by `videoFrames()`); links are opened by Claude's `web_fetch_20250910` server tool (Instagram/Facebook often show only a login wall, so the app asks for the caption or screenshots instead, with per-app tips in `IMPORT_TIP`). TikTok captions are also tried from TikTok's public oEmbed. Claude returns ingredients, steps and per-serving nutrition; edits re-estimate calories (`estimateRecipe()`). Thumbnails are 240px JPEG data URLs. The manifest has a GET `share_target`, so Share → Nourished from Instagram/TikTok/YouTube/Chrome opens `?url=&text=` and `takeShare()` imports straight away.
- **Own recipes first:** "What can I make?" matches saved recipes locally (`matchMine()`, ingredient word overlap) and shows them above web results; with 3+ strong matches it skips the web search until Glen taps "Also search recipe sites". Recipe ideas (`bookForPrompt()`) and meal plans (`planContext()`) send the saved recipes to Claude and ask it to use them first.
- **Pantry filter and sort (v13):** products have no category, expiry or quantity, so the Pantry tab sorts by name, last bought, date added, price per kg, pack price, and per-100g calories/protein/sugar/fibre (`PANTRY_SORTS`, `sortPantry()`; products missing the value go last; choice saved as `settings.pantrySort`). Filter chips (`PANTRY_FILTERS`, one at a time): Needs label, No price, High protein (≥20% of kcal from protein, the EU/UK claim rule), Low sugar / sat fat / salt (green traffic light). A Shop dropdown appears when products have a store. Search also matches the plain `generic` name.
- **Pantry categories (v15):** `CATS` (Dairy & eggs, Meat, Fish & seafood, Meat-free & tofu, Fruit, Veg, Bread & bakery, Frozen, Tins, Jars sauces & dips, Cupboard, Snacks & treats, Drinks, Miscellaneous). `catOf(p)` uses `p.cat` if set, else `guessCat()` keyword rules (`CAT_RULES`, first match wins, so order matters) on the generic name + name; nothing is migrated. Receipt scans ask Claude for a `category` and store it on new products (or ones with none). Glen can change it in the product's Edit form. Pantry has a Category dropdown (with counts) and a Category sort that shows headings.
- **Calendar (v16):** Today's date heading opens a month calendar (`calendarCard()`, `S.calOpen`, `S.calMonth`; weeks start Monday, future days disabled). Each day shows logged kcal and dots for food on/over target, exercise and weigh-ins. Tapping a day (`pickday`) sets `S.day`, so Today shows that day and every add/edit there (meals, exercise, screenshot import) saves to it; a banner with "Back to today" shows on past days. The 7-day chart bars are tappable too.
- **Today's tip (v19):** Home's tip is built from today's log (`dayTip()`, `dayTipHTML()`), in priority order: nothing logged → nudge to log a first meal (+ "Remind me daily", a Google Calendar repeating-event link from `reminderURL()`, hidden once tapped via `settings.reminderSet`); over the calorie budget → "a blow-out is fine, back on track next meal"; protein or fibre under 80% of what's expected for the share of calories eaten → vegetarian foods to add (`TIP_FOODS`); saturated fat over 20g; else "on track" + the rotating `TIPS` line. Extra rows: no weigh-in for 28+ days (or ever), no exercise for more than 7 days. Re-renders when the app comes back to the foreground. True push reminders aren't possible without a server (Web Push needs one; Periodic Background Sync is unreliable and can't pick a time), hence the calendar route.
- **Protein target and meal plans (v19):** target = 1.2 g/kg of goal weight (`proteinTarget()`), the low end of the 1.2–1.6 g/kg weight-loss range (Leidy 2015) and top of 1.0–1.2 g/kg for over-65s (PROT-AGE 2013); UK RNI is 0.75 g/kg. Sources are shown in My goals. `makePlan()` asks for ~28% of protein per main meal, diet-specific sources (`PROTEIN_SOURCES`), then `planDayMiss()` checks each day (kcal ±100, protein ≥95%, fibre ≥27 g) and `fixPlanDays()` asks Claude once to rework failing days, keeping a fix only if it's closer. Days still off are flagged in red in the plan view.
- **Units:** height ft/in or cm; weight kg, lb, or st+lb (`wUnit()`, `fmtW()`, `wInputHTML()`); stored internally as kg/cm.
- **Plain shopping names:** receipts store a `generic` name; "Add my recent shopping" asks Claude once per product for any without one (`plainNames()`), with an offline `roughName()` fallback.

## Design
Forest green `--leaf` and saffron `--olive` on soft stone, Bricolage Grotesque headings, Atkinson Hyperlegible body text. Photo-led home: hero (grain bowl), three photo cards (Log a meal, Scan food, Meal plan), then a grouped "Your tools" list. "Your tools" is a 2-column grid of photo cards (`.pfeat.tools`, v17), same style as the cards above. Photos were generated with Canva AI (`generate-image`) and embedded at 600px (Glen downloaded the 2048px originals from Canva, v18; Claude's workspace can only fetch Canva's 200px previews). Pantry and My goals have no photo yet (`.pcard.noph`: green gradient with an icon). Light and dark themes via tokens. Photos came from Canva; Glen downloaded and attached them because Claude's workspace couldn't download from Canva.
